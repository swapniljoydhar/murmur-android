# Murmur UX/UI Fix Plan

## Scope

**Only** UX/UI files in scope. No changes to data, domain, playback, storage, backup, or other non-UI layers.

### In scope
- `app/src/main/java/com/joy/murmur/ui/theme/MurmurTheme.kt` — Theme system
- `app/src/main/java/com/joy/murmur/ui/MurmurApp.kt` — All screens and composables

- `app/src/main/java/com/joy/murmur/ui/widget/` — Glance widget (separate concern)
- `app/src/main/AndroidManifest.xml` — Manifest changes

## Current UX/UI Problems

### 1. No brand identity (Theme)
`MurmurTheme.kt` uses raw `lightColorScheme`/`darkColorScheme` with muted teal/gray values. No custom typography, no component themes, no shape system, no elevation tokens. The app looks like a default Material3 starter, not a distinctive media app.

### 2. Monotonous card usage
Every list item and container is an `OutlinedCard`. Music tracks, audiobooks, documents, playlist items, chapters, bookmarks — all identical outlined cards. No visual hierarchy.

### 3. Mojibake icons
Unicode escape sequences (`Ã¢â„¢Â«`, `Ã¢â‚¬Â¦`, `Ãƒâ€”`, etc.) appear throughout `MurmurApp.kt` where icons should be. These are corrupted characters, not icons.

### 4. Plain empty states
`EmptyMusicLibraryCard`, `EmptySectionScreen`, and document/music empty states are just text in outlined cards. No imagery, no illustration, no distinctive styling.

### 5. Weak typography hierarchy
All screens use `MaterialTheme.typography.headlineSmall`, `titleMedium`, `bodyMedium`, etc. directly with no custom type scale. No distinction between display, headline, title, body, label, caption beyond Material defaults.

### 6. Inconsistent container usage
`StorageCenterScreen` uses plain `Card` while `MurmurApp.kt` uses `OutlinedCard`. `OemFixScreen` uses `Card` everywhere. No consistent container language.

### 7. Weak Now Playing / player screens
- Mini player: single row with title + play/pause button
- Music player: slider + 3 buttons + queue list in plain cards
- Audiobook player: centered layout but no prominent artwork treatment
- Read Aloud player: bare minimum controls

### 8. No component library
Every composable inline-defines its layout, padding, spacing, colors. No reusable `MurmurCard`, `MurmurButton`, `MurmurListItem`, `MurmurEmptyState`, etc.

## Design Direction (from Figma references)

The user referenced 4 Figma community files for media/reader app design. While direct access isn't available, the consistent thread across them is:

- **Rich typography** — Display/headline treatments for titles, distinct label/caption styles
- **Prominent artwork** — Album covers and book art at scale, not tiny thumbnails
- **Rounded containers** — Large corner radii (16-28dp), filled surfaces over outlines
- **Color accents** — Primary color used sparingly for actions and state indicators
- **Bottom navigation** — Or clear destination rails for main sections
- **Card libraries with imagery** — Not just text in outlined boxes
- **Calm, readable reading experience** — Generous line height, comfortable measure, subtle section dividers

## Plan: Ordered Task List

### Task 1: Build the theme system (`MurmurTheme.kt`)

**Goal:** Replace the basic color scheme with a complete Material3 theme including typography, shapes, and component themes.

**Changes:**
1. Define a custom `ColorScheme` (light + dark) with distinct primary/secondary/tertiary that works for a media app — primary for actions, secondary for accents, surface variants for containers
2. Define a custom `Typography` scale: displayLarge/Medium/Small, headlineLarge/Medium/Small, titleLarge/Medium/Small, bodyLarge/Medium/Small, labelLarge/Medium/Small, caption — tuned for reading comfort
3. Define `Shapes`: small (4dp), medium (8dp), large (16dp), extra-large (28dp)
4. Add component themes: `MurmurCard`, `MurmurButton`, `MurmurOutlinedButton`, `MurmurTextButton`, `MurmurListItem`, `MurmurTopAppBar`
5. Keep `AppearanceMode` integration (SYSTEM/LIGHT/DARK)

**Validation:** Theme compiles, light/dark toggle works, no broken references.

---

### Task 2: Create a shared component library

**Goal:** Extract reusable UI primitives from `MurmurApp.kt` into dedicated composables so screens aren't duplicating layout logic.

**New file:** `app/src/main/java/com/joy/murmur/ui/components/MurmurComponents.kt`

**Components:**
1. `MurmurCard` — Filled surface card with configurable shape, elevation, padding
2. `MurmurOutlinedCard` — Outlined variant
3. `MurmurListItem` — Leading art + title + subtitle + trailing action
4. `MurmurEmptyState` — Icon + title + description + primary/secondary actions
5. `MurmurSectionHeader` — Title + subtitle + optional action
6. `MurmurMiniPlayer` — Reworked mini player with artwork + title + play/pause
7. `MurmurProgressRow` — Current/total time labels around a slider
8. `MurmurPlaybackRow` — Previous/Play/Next centered row

**Validation:** All existing call sites in `MurmurApp.kt` updated to use components; no inline layout duplication remains for these patterns.

---

### Task 3: Fix Continue screen (`ContinueScreen` + `DestinationCard`)

**Goal:** Make the home screen feel like a destination, not a landing page.

**Changes:**
1. Replace `DestinationCard` outlined cards with filled `MurmurCard` components that include destination-specific leading artwork/icons
2. Add a hero section with app tagline and a "Continue where you left off" chip if resumable content exists
3. Improve typography: headlineLarge for tagline, titleMedium for destination titles
4. Add subtle divider between hero and destination grid
5. Replace "Open" text with icon + text

**Validation:** Continue screen renders with filled cards, hero section, proper typography.

---

### Task 4: Fix Music library screen

**Goal:** Distinguish music tracks from playlist/album/artist groups visually.

**Changes:**
1. Replace `OutlinedCard` for tracks with `MurmurListItem` (leading artwork placeholder, title, artist/album subtitle, trailing queue/playlist buttons)
2. Replace `OutlinedCard` for playlists with `MurmurCard` with cover-art-style leading element
3. Replace `OutlinedCard` for empty state with `MurmurEmptyState` (music note icon, "No music found", actions)
4. Improve search field styling
5. Replace `SecondaryTabRow` with a more prominent tab treatment or segmented control

**Validation:** Music screen uses list items for tracks, filled cards for playlists, designed empty state.

---

### Task 5: Fix Audiobook library screen

**Goal:** Audiobooks deserve prominent artwork and progress indication.

**Changes:**
1. `AudiobookRow`: Larger artwork (80dp+), title + author + progress chip, remove "Remove" from row (move to overflow or contextual menu)
2. Empty state: `MurmurEmptyState` with book icon
3. Add book cover art as background-tinted element rather than tiny square

**Validation:** Audiobook rows have prominent artwork, progress indication, clean empty state.

---

### Task 6: Fix Document library screen

**Goal:** Document list should feel like a reader library, not a file picker.

**Changes:**

**Validation:** Document rows have format icons, designed empty state.

### Task 7: Fix Reader screen

**Goal:** Reading should be calm and focused. Controls should recede.

**Changes:**
1. Reading text area: generous line height (1.45-1.6), comfortable measure, serif-friendly body style
2. Top controls (text size, search, Read Aloud) should be in a subtle toolbar that doesn't compete with text
3. Bookmarks row: horizontal scroll with pill-shaped chips instead of text buttons
4. Previous/Next navigation: icon + text, de-emphasized
5. Voice picker dialog: list with radio selection, not text buttons

**Validation:** Reader body text has generous spacing, controls are subtle, bookmarks are pills.

---

### Task 8: Fix Now Playing / player screens

**Goal:** Player screens should showcase artwork and playback state clearly.

**Changes:**

2. `ReadAloudPlayerScreen`: Document-like feel, large title, "Return to Text" prominent
3. `NowPlayingScreen` (music): Artwork + title + artist, slider, controls, queue list with compact rows
4. `MiniPlayer`: Artwork (32dp), title, subtitle, play/pause — compact but readable

**Validation:** Player screens have large artwork, clear playback state, secondary info de-emphasized.

## Risk Assessment

| Risk | Mitigation |
|------|------------|
| Theme changes break existing screen layouts | Test each screen after theme applied; keep `MaterialTheme` fallback where needed |
| Component extraction introduces bugs | Extract one component at a time, verify call sites |
| Custom typography affects reading comfort | Keep line heights >= 1.45 for body text, test with long documents |
| Icon migration misses some usages | Grep for mojibake patterns after migration |

## Open Questions

1. **Bottom navigation vs. current rail:** The current app uses top-level destinations via Continue screen. Should we add a bottom nav bar for Music/Audiobooks/Documents/Continue? (Recommended: yes, for quick switching.)
2. **Custom font:** Should we bundle a serif font for reader body text and a sans-serif for UI? (Recommended: yes, improves reading experience.)
3. **Artwork placeholders:** For music/audiobooks without cover art, should we use letter avatars or abstract gradients? (Recommended: letter avatars with primary color background.)
